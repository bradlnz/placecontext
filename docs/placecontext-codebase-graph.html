Project dependency rules

  • Application → Domain
  • Infrastructure → Application + Domain

Execution model

  • One Host process serves portal, MCP, OAuth, APIs, and schedulers
  • Durable runs are claimed atomically from PostgreSQL
  • Workloads execute as Kubernetes Jobs in-cluster or Docker locally
  • Results fan out to storage, project tables, vectors, events, and UI status

State topology

  • PostgreSQL is the system of record and tenant boundary
  • MinIO/S3 stores file artifacts; Redis holds distributed hot state
  • Qdrant or pgvector provides semantic retrieval
  • Application-layer encryption protects sensitive persisted fields
