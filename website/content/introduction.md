# A data platform built for action

PlaceContext brings connected data, agents, compute jobs, and workflows into one project. Use the data to understand what needs attention, give an agent or a job the work, and bring a person in when a decision needs judgement.

The result is a process you can run again, with recorded inputs, outputs, and decisions.

## Start with your data

Connect an existing source or import records into project SQL tables. Explore the records, define relationships, build saved queries, and create charts. Project tables hold the data; search and vector indexes provide derived retrieval views when configured.

[Explore the data platform →](/docs/data/)

## Put the context to work

Describe an outcome to the dashboard assistant or compose it in the workflow editor. A workflow can combine queries, code jobs, agent tasks, parallel work, conditions, and human responses. **Query data can appear at any stage**—before an agent, between jobs, or after a decision.

[Build your first workflow →](/docs/first-workflow/)

## Work through chat or the canvas

The dashboard assistant can inspect project context and use tools to help build and run work. Named agents have their own model, instructions, and assigned MCP connections. The workflow canvas makes the process visible, including both sides of a decision and the points where work pauses.

Chat and the editor work with the same project resources and permissions. A model connection is required for AI features; opening the workflow picker does not require one.

## Keep people in the process

Use a human checkpoint to ask for information or a Yes/No decision. The response is recorded in workflow context. A later condition determines what runs next. Agent output, AI verification, and a person's approval are separate inputs to that process.

## Own the runtime

PlaceContext is self-hosted and MIT licensed. Connect supported model endpoints, execute code in isolated jobs, and integrate through MCP, APIs, or Terraform. Infrastructure and provider configuration determine which capabilities are available in your installation.

Start with the [local quickstart](/docs/quickstart/), then read the [deployment guide](/docs/deployment/) when preparing a shared installation.
